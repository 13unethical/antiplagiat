# ТЗ: антиплагиат + ИИ-детектор для узбекского и русского языков

Версия 0.1 · 23.11.2026 · рабочий документ для разработки в Claude Code.
Макеты интерфейса лежат в отдельном дизайн-канвасе: новая проверка, отчёт, история, админ школы, суперадмин.

---

## 1. Продукт и роли

B2B-сервис для школ и вузов. Работает в двух режимах: веб-кабинет и API.

| Роль | Кто | Что может |
|---|---|---|
| **superadmin** | владелец платформы | Создаёт школы и их админов. Задаёт тарифы, лимиты проверок и срок действия. Видит все Flagged, спорные результаты, версии моделей, корпус, журнал API. Может «войти как админ» (с записью в audit log). |
| **school_admin** | админ школы | До **10** учительских аккаунтов: пригласить, отключить, задать личный лимит. Управляет API-ключом школы, настройками по умолчанию и репозиторием работ. Видит все проверки школы. |
| **teacher** | учитель | Создаёт проверки (файл или текст), видит свои отчёты и историю, скачивает отчёт, оспаривает результат («ИИ ошибся»). |

Правила:
- Лимит 10 учителей проверяется **на бэкенде** (`seats_limit` у организации, по умолчанию 10). Отключённый учитель место не занимает. Приглашённый занимает.
- Лимит проверок задаётся на месяц для организации. Опционально есть личный лимит учителя внутри него.
- Проверки через API списываются из того же лимита школы.

## 2. Архитектура и стек

```
Frontend (Next.js) ─┐
API-клиенты школ ───┼─> API (FastAPI) ─> Postgres (пользователи, проверки, результаты)
                    │         │
                    │         └─> очередь (Redis + Celery / RQ / Arq)
                    │                 │
                    │   ┌─────────────┼──────────────┬──────────────┐
                    │   │ parse+flags │ plagiarism   │ ai-detector  │ report-render
                    │   │ (CPU)       │ (CPU)        │ (GPU)        │ (PDF/DOCX)
                    │   └─────────────┴──────┬───────┴──────────────┘
                    │                        │
                    │        OpenSearch (шинглы, BM25) · Qdrant (эмбеддинги) · S3/MinIO (файлы)
```

Пайплайн одной проверки:
1. **Парсинг.** docx (python-docx и разбор XML, чтобы видеть стили и скрытый текст), pdf (PyMuPDF), OCR сканов (Tesseract `uzb`, `uzb_cyrl`, `rus`). Сохраняем текст и карту позиций для подсветки.
2. **Flagged-проверки** на сыром тексте, до нормализации (раздел 6).
3. **Нормализация:** NFC, единые апострофы узбекского (`‘ ’ ʻ ʼ ' \`` → `ʻ`), удаление невидимых символов, приведение подменённых букв к письменности документа.
4. **Определение языка и письменности** по фрагментам: uz-Latn, uz-Cyrl, ru, другое (fastText LID или GlotLID).
5. **Антиплагиат** (раздел 5).
6. **ИИ-детектор** (разделы 3–4).
7. **Сборка отчёта** (раздел 7).

Хостинг: персональные данные граждан Узбекистана по закону «О персональных данных» нужно хранить на серверах внутри страны. Схему хранения и обработки согласовать с юристом. GPU-воркер можно держать отдельно, если на него уходит только обезличенный текст. Это тоже проверить с юристом.

## 3. ИИ-детектор

### 3.1 Данные

**Есть:** около 4000 текстов, сгенерированных через API Claude, GPT и Gemini.

**Этого мало, а без человеческой части обучение не работает.** Нужно:

| Класс | Источник | Цель на старте |
|---|---|---|
| Человек | Студенческие работы, написанные **до ноября 2022** (до массового ChatGPT): архивы курсовых и рефератов вузов-партнёров, старые работы с ziyonet и сайтов рефератов, свой репозиторий (с согласия) | не меньше числа ИИ-текстов, лучше в 1,5–2 раза больше |
| ИИ | Твои 4000 и расширение (ниже) | 4000 → 10 000+ |
| ИИ после атак | Перевод, парафраз, ручная правка (раздел 4) | 30–40% всех ИИ-текстов |
| Смешанные | Документ, где часть абзацев человеческие, часть ИИ | для обучения разметки по предложениям |

Ключевые правила сбора:
- **Совпадение тем и жанров.** ИИ-тексты генерировать на те же темы и в том же жанре, что и человеческие: «напиши введение курсовой на тему X», а X взять из реальной человеческой работы. Иначе модель научится различать темы, а не авторов.
- **Баланс языков:** uz-Latn, uz-Cyrl и ru примерно поровну, плюс разные длины (от абзаца до 10+ страниц).
- **Больше генераторов:** DeepSeek, Qwen, Llama, Mistral, Grok (открытые модели можно запускать локально, это дёшево). Разные промпты («пиши как студент 2 курса», «с ошибками», «простым языком»), температуры от 0.3 до 1.2.
- **Метаданные к каждому тексту:** модель, промпт, температура, язык, тип атаки, источник. Без них не получится честно оценить качество.
- **Условия API.** У OpenAI, Anthropic и Google в условиях есть ограничения на использование ответов для обучения конкурирующих моделей. Детектор обычно под это не подпадает, но формулировки стоит прочитать.

### 3.2 Модели (от простой к сильной)

1. **Бейзлайн за день:** символьные n-граммы TF-IDF + логистическая регрессия. Быстро, дёшево, показывает, есть ли в данных сигнал.
2. **Основная модель:** дообучить **XLM-RoBERTa** (base, потом large) или **mDeBERTa-v3**. Обе мультиязычные, узбекский и русский есть в предобучении. Классификация отрезков по 3–5 предложений скользящим окном, затем агрегация на весь документ.
3. **Zero-shot признаки:** перплексия и метод в духе Binoculars на открытой мультиязычной LLM (например, семейство Qwen). Хорошо обобщаются на новые генераторы, которых не было в обучении.
4. **Ансамбль:** логистическая регрессия поверх выходов (2) и (3) плюс признаков машинного перевода (раздел 4).

Выход: вероятность для каждого предложения и доля «вероятно ИИ» в документе. Без бинарного вердикта.

### 3.3 Обучение и оценка

- Делить train/val/test **по документам и темам**, а не по отрезкам: куски одного текста не должны попасть и в обучение, и в тест.
- **Leave-one-model-out:** обучить без, например, Claude, проверить на Claude. Это главный тест того, что детектор не сломается на новой модели.
- **Калибровка:** temperature scaling. Порог выбирать так, чтобы **ложные срабатывания на человеческих текстах были ≤ 1%**.
- **Метрики:** FPR на человеческих текстах (главная), TPR при FPR = 1%, AUROC. Все с разбивкой по языку, письменности, генератору и типу атаки.
- **Отдельный тест «сложных людей»:** тексты отличников, сухие формальные тексты, тексты носителей другого языка. На таких детекторы чаще всего ошибаются.
- **Цикл улучшения:** учитель оспаривает результат → суперадмин размечает → пример попадает в датасет → новая версия модели. В админке показывать v0.3 / v0.4 с метриками и откатом.

## 4. Защита детектора от обхода переводом и хьюманайзерами

Схема обхода: сгенерировать текст на EN или RU → прогнать через Google Translate или Yandex → получить узбекский. Либо перевести UZ → EN → UZ, чтобы «размыть» стиль.

Меры, от самой важной:

1. **Аугментация в обучении.** Каждый ИИ-текст прогоняется через разные цепочки:
   - EN → UZ, RU → UZ, EN → RU через Google Translate, Yandex, DeepL и открытый NLLB-200 (он поддерживает узбекский);
   - круговой перевод UZ → EN → UZ, UZ → RU → UZ;
   - парафраз LLM-ом («перепиши своими словами»), синонимайзер;
   - ручная правка: замена 20–50% предложений человеческими.

   Всё это размечается как «ИИ» с меткой типа атаки. Без этого шага остальное не спасёт.
2. **Отдельный детектор машинного перевода.** Это третья голова классификатора: «человек / ИИ / машинный перевод». В переводном тексте свои следы: кальки, порядок слов источника, типичные ошибки сервисов перевода. В отчёте отдельный флаг «Вероятно машинный перевод». Учитель должен это видеть, даже если ИИ-вероятность невысокая.
3. **Проверка через обратный перевод.** Текст переводится на EN и RU (через NLLB или API), детектор запускается и на этих версиях, результаты объединяются. ИИ-сигнал часто сохраняется в языке-посреднике.
4. **Межъязыковой антиплагиат** (раздел 5.3) ловит перевод чужого текста, в том числе ИИ-текста, который уже где-то опубликован.
5. **Стилометрия по студенту.** Если в репозитории есть прошлые работы студента, сравнить стиль: длину предложений, служебные слова, ошибки, пунктуацию. Резкий скачок стиля — отдельный сигнал «стиль не похож на прошлые работы».
6. **Нормализация символов** (раздел 6) до детектора, чтобы подмена букв не ломала токенизацию.

## 5. Антиплагиат

### 5.1 Откуда брать базу

**Веб (узбекский и русский):**
- многоязычные датасеты на основе Common Crawl (FineWeb-2, HPLT, CulturaX и подобные), фильтр языков uz и ru;
- дампы Википедии uz и ru;
- свой краулер по целевым сайтам: ziyonet.uz, сайты рефератов и курсовых, сайты вузов, новости (kun.uz, gazeta.uz, daryo.uz и др.), lex.uz (студенты часто копируют законы). Соблюдать robots.txt, извлекать текст через trafilatura.

**Научные статьи:**
- CyberLeninka: русскоязычные статьи в открытом доступе. Проверить условия и доступные выгрузки;
- OpenAlex (метаданные) + CORE и Unpaywall (полные тексты в открытом доступе), arXiv;
- узбекские научные журналы: многие работают на OJS, у него есть OAI-PMH для сбора метаданных и ссылок на PDF;
- архивы диссертаций и закрытые базы — только по договорённости с владельцами.

**Ранее проверенные работы (самое ценное):**
- репозиторий каждой школы: работа сохраняется только при включённой галочке, согласие студента и школы оформлено в договоре и пользовательском соглашении;
- сравнение с работами других школ: показывать «работа из другой организации, 2025» без имени и текста целиком. Полный текст — только по запросу и с разрешения владельца;
- архивы старых курсовых и дипломов вузов-партнёров по договору. Заодно это человеческие тексты для детектора;
- хранить в зашифрованном виде, отдельно отпечатки (шинглы, эмбеддинги) для поиска.

**Живой поиск в интернете:**
- из документа выбрать 15–30 «редких» фрагментов (предложения с редкими словами, без шаблонных фраз);
- искать их в кавычках через поисковое API: Yandex Search API, Brave Search API, Google или агрегаторы вроде SerpAPI. Условия и цены меняются, проверить перед выбором. Bing Search API Microsoft закрыла;
- скачать топ-результаты, извлечь текст, сравнить, **сохранить найденные страницы в корпус**: так база растёт сама;
- кэш запросов и дневной лимит, видимый в суперадминке.

### 5.2 Поиск дословных и почти дословных совпадений
- Лемматизация: русский — pymorphy3 или mystem; узбекский — стеммер по суффиксам (агглютинативный язык: kitob-lar-imiz-dan).
- Шинглы по 5–8 слов → MinHash + LSH для быстрого отбора кандидатов, индекс в OpenSearch.
- Затем детальное выравнивание с кандидатом (rapidfuzz или Smith-Waterman по токенам), склейка соседних совпадений во фрагменты.

### 5.3 Перефразирование и межъязыковой плагиат
- Эмбеддинги предложений: **BGE-M3**, multilingual-e5-large или LaBSE → Qdrant.
- Одна модель кладёт UZ, RU и EN в общее пространство, поэтому перевод русской статьи на узбекский находится как совпадение (в макете это фиолетовая подсветка «RU→UZ» с показом оригинала рядом).
- Порог близости подбирать на размеченных парах «перевод / не перевод».

### 5.4 Подсчёт процента
- % совпадений = доля слов документа, попавших хотя бы в один засчитанный фрагмент (без двойного счёта).
- Исключения: цитаты в «» и "", список литературы (только строки, похожие на библиографические записи), совпадения короче N слов (по умолчанию 8), шаблонные фразы («Mavzuning dolzarbligi», «Актуальность темы», «Kirish», «Xulosa»), прошлые версии работы того же студента.
- Учитель может отключить источник, и процент пересчитывается сразу.

## 6. Flagged: защита от обхода

Проверки идут на **сыром** тексте и стилях файла, до нормализации. У каждого флага есть тип, серьёзность, позиции и количество.

| Приём | Как ловим |
|---|---|
| **Подмена букв** (кириллическая «а» U+0430 вместо латинской «a» в узбекском, или латинские a, e, o, p, c, x, y внутри русских слов) | Для каждого слова определяем письменность каждой буквы (Unicode Script). Слово, где смешаны латиница и кириллица, — подозрительное. Используем таблицу похожих символов Unicode (UTS #39 confusables). Флаг: «в слове *mаqsаdi* 2 кириллические буквы». После этого приводим буквы к письменности документа и проверяем дальше. |
| Исключения, чтобы не было ложных флагов | Разные апострофы в oʻ / gʻ — норма, без флага. Отдельные слова целиком на другой письменности (названия, цитаты) — норма. Флагуем только смешение письменностей **внутри слова**. |
| Невидимые символы | U+200B, U+200C, U+200D, U+2060, U+FEFF, мягкий перенос U+00AD, необычные пробелы — считаем, удаляем, флагуем при массовом использовании |
| Скрытый текст в docx | Белый или фоновый цвет, размер шрифта ≤ 2 pt, атрибут hidden (`w:vanish`), текст под картинкой, крошечные текстовые поля |
| Текст картинкой | Страницы или большие изображения с текстом → OCR, флаг с долей текста, найденного только через OCR |
| Подмена текстового слоя PDF | Сравнить извлечённый текст с OCR той же страницы: если сильно различаются, это флаг (испорченная кодировка символов) |
| Р а з р я д к а | Слова, разбитые пробелами на буквы, или увеличенный межбуквенный интервал |
| Злоупотребление кавычками | Если в кавычках больше ~25% текста, исключение цитат отключается для этой работы и ставится флаг |
| Текст под видом библиографии | Исключаются только строки, похожие на библиографические записи. Обычные абзацы после заголовка «Список литературы» проверяются |
| Синонимайзер | Аномальная доля редких слов и неестественных синонимов — флаг низкой серьёзности |

## 7. Отчёт: текстом и файлом

Форматы:
- **В интерфейсе:** документ с подсветкой (совпадение / межъязыковое / ИИ / Flagged), источники, сравнение бок о бок.
- **Текстом:** короткая сводка для копирования и для API (`format=text`).
- **Файлом:** PDF (основной, с подсветкой, ID проверки и QR-кодом для проверки подлинности отчёта), DOCX, JSON.

Пример текстового отчёта:
```
Проверка CHK-2026-0001847 · 23.11.2026
Работа: Kurs_ishi_Elektron_tijorat.docx · узбекский (латиница) · 4 812 слов
Совпадения: 23% (7 источников, 2 межъязыковых)
Вероятный ИИ-текст: 41% предложений
Машинный перевод: вероятно, 3 фрагмента
Flagged: 3 — подмена букв (27 символов), невидимые символы (14), белый текст (1 абзац)
ИИ-оценка — вероятность, а не доказательство.
Полный отчёт: https://…/r/CHK-2026-0001847
```

## 8. API, данные и права

**Аутентификация:** веб — JWT/сессии; API — ключ организации (в базе только хэш, показывается один раз, можно перевыпустить).

**Основные эндпоинты:**
- `POST /v1/checks` — файл (multipart) или текст + опции (`checks: ["plagiarism","ai"]`, `exclude_quotes`, `exclude_bibliography`, `min_match_words`, `save_to_repository`, `webhook_url`)
- `GET /v1/checks/{id}` — статус и результат
- `GET /v1/checks/{id}/report?format=pdf|docx|json|text`
- `POST /v1/checks/{id}/dispute` — оспорить результат
- `GET/POST/PATCH /v1/org/teachers` — для school_admin, лимит 10
- `POST /v1/org/api-keys/rotate`
- `/v1/admin/*` — только superadmin: организации, тарифы, лимиты, модели, корпус, flagged, disputes
- Вебхук по завершении проверки.

**Таблицы:** organizations (seats_limit=10, monthly_quota, plan, valid_until), users (role, org_id, status, personal_quota), api_keys, checks, documents, matches, ai_segments, mt_segments, flags, sources, corpus_documents, repository_documents (consent, org_id), disputes, model_versions, audit_log.

**Юридическое (проверить с юристом):**
- согласие на хранение работ в репозитории; договор со школой;
- локализация персональных данных в РУз;

## 9. Этапы разработки (по ним давать задачи в Claude Code)

1. **Скелет:** монорепо, FastAPI + Postgres + Next.js, auth, роли, организации, лимит 10 учителей, приглашения.
2. **Загрузка и парсинг:** docx, pdf, OCR, карта позиций, нормализация, **Flagged-модуль** с тестами на подмену букв.
3. **Антиплагиат v1:** шинглы + OpenSearch, первый корпус (Википедия uz/ru + целевой краулинг), исключения, подсчёт процента.
4. **Отчёт:** экран отчёта по макету, PDF/DOCX/JSON/текст, QR-проверка подлинности.
5. **Панели:** админ школы (учителя, API-ключ, настройки) и суперадмин (школы, лимиты, flagged).
6. **Публичный API** + вебхуки + документация.
7. **Детектор v0:** сбор человеческих текстов, бейзлайн TF-IDF, затем XLM-R; аугментации перевода; оценка leave-one-model-out.
8. **Семантический и межъязыковой поиск:** BGE-M3 + Qdrant.
9. **Живой поиск в интернете** + пополнение корпуса.
10. **Детектор машинного перевода, стилометрия, цикл disputes → дообучение.**
